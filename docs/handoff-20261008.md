# CMFM handoff (2026-10-08)

From the DLSS project agent to the CMFM agent. Nothing is built yet. This
folder holds the decisions, requirements and research so far.

## What CMFM is

CMFM (Configuration Menu For Mods) is the user's framework for Monster Hunter:
World mods. Decided with the user on 2026-10-08:

1. **One name, two parts:**
   - CMFM Core: the early native loader, plugin API and hook coordination;
   - CMFM Menu: in-game settings, status pages and popups.

   The user floated "CMFMPL" (plus loader); the recommendation was to keep one
   name, so users only ever hear "install CMFM". Confirm with the user if
   naming comes up.
2. **CMFM replaces Stracker's Loader.** With CMFM installed, existing Stracker
   plugins run unchanged and no `dinput8.dll` or `loader.dll` sits in the game
   folder. The user's reason: Stracker's Loader "does nothing special", and the
   fewer loaders and bandaids over the exe the better.
3. **Native first.** The plugin API is C, and no managed runtime runs in the
   frame loop. SPL stays the home for C# gameplay mods; CMFM coexists with it
   and does not compete.
4. **The DLSS mod is the first client.** Until CMFM exists it ships standalone
   as `winmm.dll` + `mhw_dlss\`, which works under MO2 without force-load
   (v0.13.9, game-52). Later it becomes a CMFM plugin and keeps the standalone
   mode.

## Suggested first steps (propose to the user, then go)

1. **Measure the entry slot.** One read-only run that records when each
   candidate delay import loads relative to CRT init, dxgi.dll and
   D3D12CreateDevice. Do it under MO2, then with the Steam overlay on and off.
   Pick CMFM's slot from data (open question 1).
2. **Core skeleton:**
   - the proxy entry;
   - a phase dispatcher (pre_main, win_main, device_created,
     swapchain_created, game_ready);
   - the C plugin ABI (`cmfm_plugin_info`, `cmfm_plugin_init`, a versioned
     `cmfm_api` table);
   - per-plugin folders and logging.

   Unit-test the ABI tables, ordering and path handling.
3. **Stracker shim:**
   - a `loader.dll` with the exact four symbols and an `Initialize` that does
     nothing on a second call, forked from Stracker's code with credit;
   - load it by full path, then load the plugins at Stracker's moment;
   - verify against the test set, with and without leftover Stracker files.
4. **Hook coordination:**
   - one owner per D3D12/DXGI entry point;
   - the presentation-owner role for the DLSS mod;
   - menu drawing into the game-facing back buffer before Present.

   Test with the DLSS mod's frame generation on.
5. **CMFM Menu:** typed settings, popups, status pages and input capture. The
   DLSS mod's settings are listed in the requirements doc.

## Open questions for the user

1. **CMFM's entry slot:**
   - host winmm.dll and chain-load the DLSS mod and SPL;
   - another early delay import, chosen after measuring (step 1);
   - pre-CRT only via Steam overlay or force-load.
2. **Menu technology and look:** ImGui, or something styled like MHW's UI?
3. **Settings storage:** per-plugin files (recommended), or a central store
   with import and export?
4. **Stracker replacement in CMFM v1 or later?** v1 is recommended: it is
   small and makes CMFM useful on day one.
5. **Licence** for CMFM.

## Coordination with the DLSS project

- The DLSS repository (`D:\mh world modding\dlssupdate`) is read-only from
  here. Requirement changes are agreed with the user and recorded in
  `docs/requirements-dlss-mod.md` here. The DLSS repository keeps only a
  pointer (`docs/cmfm-requirements.md`).
- DLSS mod facts CMFM must respect:
  - it hooks CreateDXGIFactory2 and D3D12CreateDevice (game call site RVA
    0x23a4e2e) and the game's NGX startup entry (RVA 0x273f230);
  - it routes the game's swap chain through Streamline's proxy;
  - it owns Reflex markers and pacing;
  - it keeps Streamline and NGX loaded until process exit;
  - single-instance mutex: `Local\mhw_dlss.instance.<pid>`;
  - NVIDIA DLLs are loaded by full path from its own folder and verified by
    SHA-256.
- Clones of the Stracker and SPL sources made during the review are under
  `D:\mh world modding\dlssupdate\local\loader-review-20261008\` (read-only
  reference). Clone your own copies into `local/` here if you need to build
  or diff them.
